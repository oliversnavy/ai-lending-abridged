LLMs, tools, skills, and middleware composed into a deep-agent system with short- and long-term memory, a three-critic feedback lifecycle, and censoring-aware eval methodology for a non-deterministic system — demonstrated end to end on a real credit-risk-ranking task, not a toy.

Honest disclosure, up front: this repo is a deliberate fork-and-strip of a larger, private, multi-month research project I'm running on long-term memory in deep agents (targeting an academic paper). The harness engineering shown here — orchestration, sandboxing, memory architecture, eval discipline — is real and complete. The research project's own novel contribution — a sequential, capital-constrained pricing mechanic, and the empirical findings about what helps agents use memory well — is intentionally not included; it's reserved for publication. What's here is the generic infrastructure underneath it, re-platformed onto a simpler, standard, publicly-available task (public LendingClub data, never any employer's or proprietary data) so it can be shared without exposing unpublished research.
What this demonstrates

Mapped directly to real agent-engineering work

1

Multi-agent patterns & state management

A main agent delegates to a sandboxed general-purpose subagent (Docker, read-only project mount, --network none). Short-term memory is LangGraph message state managed by context-editing + overflow-recovery middleware; long-term memory is a distilled, capped, cross-episode learnings loop — not a vector store.

2

Agent architecture & orchestration

A deliberate middleware stack and ordering (guardrails → recovery → time/token awareness → context editing → overflow recovery), composed differently per run config from the same build_graph() function.

3

Eval methodology for non-deterministic systems

Independent, subprocess-isolated re-scoring (the agent's self-report is never authoritative); Harrell's C instead of AUC to handle censored outcomes correctly; first-class degenerate-model detection, not just a low score.

4

Advisory-to-embedded delivery range

The advisor config escalates to a senior-reviewer LLM at defined checkpoints — the advisory point. The ltm_full config is a fully embedded, memory-carrying loop — the embedded point. Same harness, same code, different composition.

5

Trace-mining & continuous improvement

A three-critic lifecycle mines each episode's trace to improve the next one — and the repo documents a tried-and-rejected alternative (static every-turn reinjection) that caused episodes to collapse into copying, kept in the codebase as a defended tradeoff, not hidden.

One honest gap from this run: the mid-episode critic fires on a turn count, and this task turned out simple enough that the agent solved it in very few main-agent turns (most real work happened inside one subagent delegation) — so it never actually fired here, even though it's confirmed correctly wired.
